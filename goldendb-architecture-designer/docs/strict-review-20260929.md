## 发现及修改建议

### A01 / P1：CN仍存在跨中心兜底（已复现）

位置：app.js:2156 `getEligibleServers`、`placeTenantCnRolesByPool`。
探针目标为中心B的1个CN，仅提供中心A可用主机，实际CN落到A。GTM/管理已在D2限制目标中心，CN尚未同步。
影响：总实例数可能看似完整，但不符合逐AZ独立承载和预期组网分布。其他性能红线可能提示问题，不能代替放置规则。
建议：CN严格限制目标中心与资源池；缺少主机保持未落位。测试同时核对逐AZ数量而不只核总数；不修改副本或异地缩减规则。

### A02 / P1：数量估算未表达单实例不可拆分（已复现）

位置：app.js:1847–1866 `calculateComponentRequirement`；1883起 `calculateMixedServerAnalysis`。
单个16核实例、单机8核、预留0：返回servers=2、effectiveMaxInstances=1。两台8核并不能承载单个16核实例。异构CN和逐Group磁盘的平均值也可能掩盖最大实例。
影响：当前选定布局已有D1/D2红线兜底，但独立/混部候选台数可能被误读为可部署方案，推荐表与风险含义不一致。
建议：把“资源总量下界”和“逐实例适配/完整落位结果”分开；无法适配时输出明确不可行原因，不生成虚假的有限可行台数，也不要把Infinity传播至图表/Excel。各候选布局分别校验。

### A03 / P1：磁盘是原始盘容量口径，未完成净可用空间模型（静态确认）

位置：app.js:1143、1160以单盘容量×盘数计算diskTb；可用量由通用reserveRatio折减。
缺少数据盘RAID净容量、热备、文件系统、日志/索引/临时空间独立预算；磁盘使用率<80%未与CPU/内存预留独立建模。增长仍取客户输入，未强制或明确核验三年窗口。
影响：存在数据盘可用空间高估风险。已有DN Group容量与磁盘水位检查不能证明满足三年实际存储需求。
建议：接续S02，明确定义原始/净容量和数据量口径，避免重复扣减；单独磁盘水位与年限；RAID0需风险确认。不能自动假定所有机型已具有RAID冗余。

### A04 / P2：异常组件身份仍可套用默认资源（已复现）

位置：app.js:2226 `getRoleResourceDemand`。
已存在租户的CN999，即使没有对应角色规格，也会回退租户默认8核/32GB，底层canPlaceRoleWithinWatermark返回true。
影响：当前普通UI未复现主动生成CN999；这是底层身份契约漏洞，未来导入、编号错误或其他调用可能把不存在的角色当作合法资源。不能宣称当前全部方案都出现此错。
建议：依据预期角色集合校验租户、类型、Group、CN序号与副本序号；GTM使用实际绑定组身份；缺失/越界拒绝，不能仅靠字符串形状判断。

### A05 / P2：自动推荐只够正常容量，却触发自身故障红线（场景确认）

T2、B1、B2均出现自动CN数量正常吞吐满足、单机损失后不足。示例T2租户1：单AZ2×1120=2240TPS，目标2000TPS；失1台后1120TPS不足。
这不是“预警失效”，预警正确；歧义在于用户可能把“推荐”理解为完整生产容量已满足。
建议：先确认默认目标是单AZ完整负载，还是同时要求该AZ内再失一台仍完整承载。若后者，按实际规格和物理机损失重新求解；否则明确标注“正常负载建议，未满足故障余量”。不得静默变更旧方案数量或在POC一律增加资源。

### A06 / P2：高可用说明比证据状态更肯定（静态确认）

位置：app.js:4263 `renderHaGuide`、4298起Team数量/低水位函数。
Team和水位从部署模式推导，页面仍有“已按资料核对”的二次校验说明；但故障检查明确未验证版本、gSync配置、仲裁、复制追平与RPO/RTO。
建议：区分资料示例、客户配置、已验证演练；无版本/配置证据不得将启发式Team规则表示为生产高可用确认。保留已实现的逐Group覆盖与性能不足提示。

### A07 / P2：性能与联合负载仍是工程估算（证据缺口）

已有来源状态提示和独立在线/跑批口径，但填写来源不验证真实性、适用机型/版本/SQL组合。IOPS、网络、回放和共享DN/GTM并发瓶颈未有完整实测模型。
建议：继续结构化标定适用范围及证据失效条件；“配置充足”“性能初算满足”“生产已验证”分开显示。RTO/RPO和跑批时限需实际演练/压测，不依据线性TPS推断认证。

### A08 / P2：CN故障测试脚本与折叠UI失配（测试失败）

tests/remediation-cn-failure.mjs:52未展开在线数量设置就fill，30秒超时。未达到该脚本后续验证步骤，不能把本套算为通过。
建议：确认后只调整测试交互步骤，不降低原断言；重新执行整套并核验故障红线。不属于已经证明的计算回归。
