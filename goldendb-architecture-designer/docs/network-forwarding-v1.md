# 设备有效 FIB 与逐跳转发契约 v1

2026-10-31，P02b3b2a2。材料位于 `connectivity.routing.forwarding`。FIB 指设备用于转发的有效路由表；本模块只计算已声明的、按目的地址确定的静态模型。不会连接设备、改配置或把计算到达认证为实际业务可达。`canDeploy=false` 保持。

## 填写与输入

先完成库存接口、网段/VRF、组件端点、有向业务连接、主机有效路由和 `routing.fabric`。不要从本测试地址、端口或设备型号生成生产默认值。

|字段|要求|
|---|---|
|schema|goldendb-network-forwarding-v1|
|targetVersion|与设计的准确 GoldenDB 版本/补丁一致；设备系统版本单独填写|
|review.coverage/source|unknown 或 declared-complete；附采集范围、时间、配置/证据位置；不接受 verified 或手填“可达”|
|tables[].id/deviceId/vrf|唯一表 ID、fabric.devices 中设备、明确 VRF；同设备/VRF 只能一份有效表|
|deviceOsVersion|精确对应设备 osVersion；不一致阻断，缺失未评估|
|mode|destination-only；无法将策略选择归并为本模型时填 unknown|
|coverage/source|表完整性声明和资料来源；缺项不能按完整 FIB 计算|
|routes[].id/destination|表内唯一 ID；规范 IPv4/IPv6 CIDR，主机位必须为零|
|kind/interfaceId/nextHop|direct：当前设备/VRF 的出口，nextHop=not-applicable；via：当前出口及同网段普通单播下一跳；blackhole：后两项均填 not-applicable|

例如某设备的一条目的路由如下。地址仅为文档示例，不能直接用于生产：

```json
{"id":"TO-DB","destination":"192.0.2.0/24","kind":"via","interfaceId":"R1-TRANSIT","nextHop":"198.51.100.2"}
```

前提是 R1-TRANSIT 确实属于该设备、当前 VRF 和包含下一跳的已声明出口网段，下一跳接口、方向邻接、后续 FIB 和返回链路均有对应资料。完整合成示例见测试产物 `forwarding/synthetic-valid.json`；待填写模板来自页面导出，不能用合成样例充当真实评审材料。

## 计算与结果

1. 每条业务连接分别计算正向和返回，不要求经过相同设备。
2. 主机起始表必须有来源、版本、完整性及有效目的选路声明；绑定路由必须是唯一最长前缀匹配。更具体路由或多候选不能被人工绑定绕过。
3. via 从现有 gatewayBindings 的具体设备接口开始，核对出发接口、网关地址、VRF、地址族与有向邻接。
4. 在每设备/VRF 的有效 FIB 中选唯一最长前缀；同长度多候选保留未评估，不自行猜测优先级或 ECMP。
5. direct 必须从正确目标网段/VRF 的设备接口，沿明确方向邻接交付到具体目标接口。via 必须解析唯一下一跳接口，再继续查表。
6. 对固定目的、无地址转换、无策略路由的确定性模型，同设备/VRF 重复到访构成循环。输出设备和路径方向。无路由、命中黑洞、错误出口、所用转发禁用或路径 down 阻断；缺 FIB/邻接、未知状态、特殊地址或不支持的语义保留未评估。
7. 不使用的备用 down 接口不自动阻断当前流量。IPv4 禁用不自动代表 IPv6 禁用；接口级例外未能归并成有效声明时不能填写 enabled。
8. 每方向最多 64 个设备处理步骤；主机及设备路由匹配合计最多 100000 次；设备表最多 1000、单表最多 1000 条、设备路由总计 5000 条。超预算未处理部分保持未评估，不推断成功或无循环。外层评审材料仍有 4 MiB 限制。

结果分层：逐跳行的“声明逐跳待实测”只表示所录路径在本模型中算到目标；父层路由、接口、设备资料和生产证据仍可能阻断或未评估。应以整体评审结果为准。本机/直连不由本模块重复认证，继续由已有路由与邻接模块检查。缺 forwarding 或缺 fabric 的旧材料保留未评估。

新增 `network-hop` 行及正向/返回 traces，JSON 保留路径结构，HTML/Excel 保留路径说明，SVG 显示统一生产门禁状态。配置变化进入既有 network 能力绑定，旧版本支持声明须重新核对。

## 边界与后续

本模型没有实现动态路由收敛、源地址/端口策略路由、ECMP 多路径、递归网关、VRF 泄漏、接口级转发例外、链路本地 IPv6 作用域、隧道、真实 ARP/ND、链路/MTU/LB/VIP/NAT、设备有序或有状态 ACL。没有这些材料时不应把本模型替代设备真实行为。

下一步 P02b3b2b1：物理链路/端口、MTU 和故障域资料及路径约束；随后 b2b2：LB/VIP/NAT/状态规则；b2b3：故障路径与实测证据闭环。生产还需要指定 GoldenDB 版本支持、业务负载、正常/故障容量、选主/仲裁、备份恢复与上线回退验证。

## 参考与校验

已阅读 GitHub 上 [Batfish 流量结果定义](https://github.com/batfish/batfish/blob/master/docs/flow_dispositions/README.md)，借鉴循环、缺路由、丢弃和资料不足分别处理的原则；本模块独立实现，未移植 Batfish，也不将其边界交付启发式等同于具体数据库端点可达。资料核对日期 2026-10-31，读取副本与哈希保存在本批 reference-check.json。

283 项逐跳专项包含双栈 1/2/3/10/64 跳、65 跳未知、往返不对称、最长前缀/黑洞/循环/缺项/预算、旧材料兼容和 216 种三节点有限图独立结果对照。图枚举用于核心选路器，部分自循环人工图还会被上层 fabric 的自邻接规则阻断，不能作为可部署网络样例。完整页面、导出和回归结果见本批验收记录。

## 2026-11-01 端到端MTU补充（P02b3b2b1b）

逐连接/方向包长目标已接入计算路径与物理结果，详见 [network-mtu-v1.md](network-mtu-v1.md)。via使用实际逐跳邻接，direct使用方向邻接；physical输出已知有效IP MTU和配置网段MTU，二者共同约束。旧材料缺packetTargets显示未评估，不自动补成通过。未知转换/分片策略不假设包长不变；本机连接仅外部网络MTU不适用。界面与导出同源，修改目标会使网络能力绑定失效。只完成静态声明检查，未批准生产；下一步b3b2b1c备选链路/共享故障域/带宽故障容量，其他旧计划继续开放。
