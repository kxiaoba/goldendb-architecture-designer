# GoldenDB组网产品与生产可实施性评估

日期：2026-10-28；基线d591ab9，P01第一阶段。评估依据为当前源码、用户60台用例、已运行测试及下列权威资料。未获得真实生产配置，本文中的“缺失”表示当前工具/项目证据不足，不断言客户现网没有该能力。

## 产品目标与当前结论

产品目标调整为：**输入真实项目约束，生成经审查、可复现、可部署、可验证、可回退的GoldenDB生产组网设计包**。不能以“画出图”或“组件装得下”作为完成条件。

当前工具已具备较多数量、身份、落位和资源必要条件检查，但输出尚不构成可以直接执行的生产部署包。确认缺少版本化部署参数、真实物理故障域与网络配置、可验证的容量/故障恢复证据及实施闭环。用户提出的生产目标合理；目前宣布“直接上生产可运行”缺少依据，应按下列分阶段门禁实现。

最终交付必须区分：①规划草案；②已评审的详细设计；③实验环境验证过的部署包；④指定生产环境演练/验收记录。环境选项production仅启用规划规则，不自动等同④。未核实、过期或与本次设计版本不匹配的证据不能计为通过。

## 60台用例的生产判断

结构要求已明确：两机房各30台；租户分片24/3/1，DN168、业务CN18、每租户独立GTM合计18、管理6、运维CN2，共212实例；全部主在本地，每组两侧3+3，副本跨主机、每机≤4。CN跨租户共宿已获用户确认。

本批固定初始布局调整后，租户1在本地21台DN主机上为3台2主+18台1主；租户2为3台1主+18台0主；租户3为1台1主+20台0主。合计28个DN主为7台2主+14台1主，各租户及合计差都≤1。B侧仍0主。硬件、主从实际负载与故障后能力尚未知，不能据这些整数推算生产TPS或RPO/RTO。

本方案保留“管理独立、运维CN独立、DN不与CN/GTM混布”的当前工具策略；这属于本用例工程边界，并非已验证的所有GoldenDB版本通用强制规则。原历史基线JSON是R18输入演示，不能当成本次新布局自动覆盖现网。

## 生产实施包最小目录与验收规则

建议目录：00-设计版本与审批、01-业务/SLO、02-版本支持矩阵、03-物理库存与故障域、04-实例/主从/端口清单、05-网络ACL与链路、06-容量/故障预算、07-安装/参数/账号、08-备份/恢复/灾备、09-监控/值班、10-上线/回退、11-测试与签字。

每个条目记录：需求ID、设计版本、对象/故障范围、目标值与单位、来源文件/版本、核验方法、证据位置/时间、责任人、结果（未知/用户声明/已核验/失败）、适用条件与失效条件。任何必需项缺失/失败/过期或变更后未复验，均不能升级生产准入状态。完整字段填写只是材料齐备，仍须核验实际环境。

上线门禁应分别检查：设计无矛盾；库存/网络/安全/版本匹配；正常与故障容量/性能达标；备份可恢复；可观测性与值班就绪；应用连接/路由/事务一致性正确；演练与回退闭环；所有P0关闭。数据迁移后的首次业务写入是回退分界，必须考虑反向同步/对账及外部业务副作用，不能简单切回旧库。
