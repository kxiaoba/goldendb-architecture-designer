# 物理备选路径与单活动选择 v1

2026-11-01，P02b3b2b1c1。此扩展核对**声明快照中当前选择的物理路径**，并单独检查其他候选路径；不计算路由协议/STP收敛或自动故障切换。

## 使用方式

在 connectivity.routing.physical 的 paths 中登记同一 adjacencyId 的多条候选路径，并增加 selections：

```json
{
  "selections": [{
    "id": "SELECT-A-B",
    "adjacencyId": "ADJ-A-B",
    "activePathId": "PATH-ACTIVE",
    "mode": "declared-single-active",
    "source": "填写与当前设计和时间相符的选路/设备配置材料编号"
  }]
}
```

- selections 为清单，最多5000项；同一邻接只能有一个选择。activePathId 必须存在且属于该邻接；不能引用返回方向或其他邻接的路径。
- mode 仅 declared-single-active 或 unknown。activePathId 可为 null 表示未知；unknown、缺来源或无效引用都不猜测活动路径。不支持 automatic、ECMP、聚合等策略。
- 旧资料每邻接仅一条物理路径且无选择声明时，沿用原逻辑。若显式填写了未知选择，不能因只有一条候选便忽略未知。
- 同一邻接存在多条候选但没有有效选择时，不取第一条、不自动挑 up 的路径；重复/缺选择阻断或未评估。
- 正向和返回是不同有向邻接，选择独立声明。这里不验证两方向选择是否符合具体交换/选路协议的控制平面约束。

## 结果解释

|结果类别|含义|对当前路径的影响|
|---|---|---|
|network-physical|已选路径的端口/线缆/交换转发/MTU检查|参与当前路径与端到端MTU结论|
|network-path-selection|声明活动路径、候选列表及来源|展示选择，不代替路径内容检查|
|network-physical-alternative|未选候选的独立路径检查|状态和具体原因单独展示；不作为当前活动路径|

当前选中的路径 down、断路或MTU不足会阻断；即使有好的备用路径，也不会自动改选。未选路径的运行状态 down、MTU不足或断路单独显示“阻断”；候选结果不抹掉其缺陷，也不反向证明当前路径失败。物理检查器额外返回 alternativeIssues，保留候选的路径ID、邻接ID、原因与严重度；页面和导出从同一结果行显示诊断。

清单自身的错误（重复物理端口、非法字段/单位、无效资产引用等）仍是整体材料错误。缺失来源或超出清单/单路径预算，也不能当完整材料通过。“未选故障不污染当前路径”不代表允许无效库存静默通过。

所有当前路径先检查，之后才检查备选；累计10000段预算不会先被备用路径耗尽。单路径128段、全路径5000项的原有边界不变；预算用尽的候选显示未评估，不伪报断路，也不宣称可切换。

端到端MTU只聚合 network-physical 类的当前路径结果，排除备选和选择说明行，防止将同一邻接的不同候选误判重复或混合计算。实际业务包长目标、返回路径及版本支持声明仍按现有规则检查；选择变化会使原网络能力绑定失效。

## 生产使用边界

- 当前选择是资料声明，工具没有读取运行设备的真实活动状态或认证来源。
- 候选静态通过不能证明故障后会被选中，亦不能证明控制平面收敛、无环、状态防火墙会话或应用重连成功。
- 路径ID不同不表示物理独立。两条路径可共享端点、端口、交换设备、电源和管道；本批不输出“冗余满足”结论。
- 合成测试中的交换转发绕行只用于验证选择、方向、状态、MTU和预算代码；未验证其STP/FDB或具体设备实现，不可复制为生产组网。
- 新增候选不会增加服务器、实例或备机数量，不改变60台落位和主均衡。canDeploy=false始终保留。

下一阶段 b1c2：共享故障域与跨目录资产别名、带宽/超卖及故障剩余容量。控制平面、自动备选策略、完整故障后的重新选路与业务实测仍保留在b3，不以单路径静态通过代替。

## 参考与设计判断

参考 [Batfish项目的可靠性检查目标](https://github.com/batfish/batfish)及[转发分析文档](https://github.com/batfish/batfish/blob/master/docs/forwarding_analysis/README.md)：故障条件、完整路径和多候选分析需明确建模。本工具独立实现有限声明检查，不具备Batfish完整数据平面或符号验证能力。采用显式选择、未知不猜测、当前与候选分开报告是本项目的实现决策。
