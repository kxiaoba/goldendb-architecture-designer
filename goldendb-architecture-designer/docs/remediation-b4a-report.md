# B4a 租户主分布策略与严格 DN 落位

日期：2026-09-09。本地保存，未提交或发布。继承未发布 B3c。

## 已实现

两模块每租户增加正常运行主分布策略：中心 A、中心 B、生产中心均衡。默认均衡只选当前模型的生产中心；两地三中心和三地五中心仅在前两个中心放正常主。单机房选择 B 会明确阻断，不静默改回 A。此策略是规划目标，不是 GoldenDB 在线切主命令，也不代表故障后永远禁止跨地域切换。

业务按同一目标函数计算各中心 DN 实例、CPU/内存/磁盘需求、同 Group 跨机数量下限以及实际落位。从副本按目标主中心起点轮转到各中心；这是当前规划分布策略，不等同于厂商版本的仲裁或复制配置。仍须按实际版本确认。

活跃 DN 落位路径只使用目标中心、指定租户资源池内满足容量、水位、密度、隔离和同 Group 跨机条件的服务器。不再越界兜底。核验每个副本恰好出现一次且中心正确；缺失/重复/错中心进红线、风险和两图说明。反推未落位时整体资源状态也为不足。

两图显示每租户策略、分片 × 副本 = DN 实例，以及实际承载服务器台数。共享服务器可被多个租户计入各自承载数，不能把各租户台数简单相加当集群去重总数。Excel 租户资源新增主分布策略列，副本明细仍来自实际落位。

## 验证结果

- 主策略18/18：两模块A/B/均衡，目标中心与实际位置，业务每中心需求与实际实例数一致；三个租户分别采用不同策略；同城双中心/两地三中心/三地五中心及CN/DN混部；手工分片保留；单中心B阻断；未落位红线。
- 增长及手工值19/19；两模块字符/响应式/实际PNG和Excel下载40/40；合计77项。
- 实际下载工作簿另经逐格模型核验，结果见 `b4a/evidence/xml/xml-workbook-validation.json`。已查看多租户主策略拓扑截图；未做真实Excel/WPS客户端核验和数据库实测。

## 发现的限制，不能视为已解决

三个租户共用共享池时，当前贪心分配出现未落位；使用独立池的对应场景完整。没有通过恢复越界兜底掩盖它。共享池用例验证的是失败被正确标红，不是成功落位。下一批需改进可行解搜索或给出明确额外资源需求。

资源反推不改变客户服务器总量，现有主机组的中心配额不一定支持主集中策略，资源不足会失败；目前不是自动优化中心配额的完整求解器。R04只完成活跃DN路径的严格约束，其他组件/遗留路径不算全部关闭。R03故障接管、版本仲裁及多地域完整性、R12所有组件可装入仍待继续。现有整体评分也不能充当生产可靠性证明。
