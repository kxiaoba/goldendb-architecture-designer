## 2026-09-12 本地验收记录

入口：业务测算的租户编辑区增加“单场景 / 在线与跑批”及 CN/DN 自动或手动规格。在线与跑批分别设置标定、CPU 水位、增长、数量；跑批支持 SQL QPS、数据库 TPS、处理量/有效窗口。缺少跑批标定时不生成有效方案，不套用在线单核值。两场景仍属于同一个租户，共享 DN 数据与 GTM。

计算：目标吞吐乘本场景增长系数的规划年限次方。SQL QPS 除以该场景每事务 SQL 数；处理量除以有效窗口秒数。每生产 AZ 的 CN 数量为 max(2, ceil(目标吞吐 / 单核标定 / CPU水位 / 规划物理核))，再应用原取偶规则；手动数量保留，不足标红。自动最终规格重新核验吞吐，手动规格按实际核数/内存装箱，不偷偷提高。内存自动比例仍为工程假设，不是厂商保证。

测试示例：在线 16000 SQL QPS / 20 = 800 TPS，16C/64GB、50 TPS/核、70%水位，生产 AZ 各 2 CN；跑批 3600万业务单位 / 2小时 = 5000单位/秒，16C/96GB、100单位/秒/核、70%水位，关闭取偶时生产 AZ 各 5 CN。两生产中心各7 CN，灾备中心按现有比例取4 CN；18实例合计288物理核、1568GB。该例仅用于程序算式测试，不是银行系统标定推荐值。

共享 DN：未提供混合负载等效规划 TPS 时只按在线与数据量初算并持续标红；低于在线目标的混合输入不能降低在线资源，采用在线下限并提示复核。手动 DN 大于标定核数不外推性能，内存低于标定比例也提示未验证。不得把在线和跑批不同单位直接相加。
