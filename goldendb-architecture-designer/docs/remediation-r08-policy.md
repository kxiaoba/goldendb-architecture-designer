# R08 低副本与集中式初算边界验收记录

日期：2026-10-27。基线eed18e3加已验证未提交R07；未覆盖原项目后续修改。范围为主页面业务测算/资源反推，不更改固定数量工具。

## 已核实的问题

1. 生产单机房业务样例：保留1副本后，Excel租户校验仍显示通过，原有DN故障检查虽已告警，租户状态和生产结构结论不一致。
2. 集中式业务样例：当前固定1 Group，但性能初算需要5 Group，Excel仍显示通过，页面只作一般提示。
3. 反推集中式样例：输入1副本按既有生产规则调整为4；缺逐租户输入/实际/参考基线说明，且没有业务吞吐和匹配性能标定，不能从库存充足推断性能满足。

原始反例和修复后结果分别保存baseline-defects.json/fixed-probe.json。反例同时可能有其他既有风险，本批不声称原方案完全无告警。

## 最终规则与理由

|条件|门禁结果|处理|
|---|---|---|
|生产实际仅1副本|未通过|任一该Group的DN宿主机失效会失去全部在线副本；加入部署红线、Excel未通过及PNG警示|
|生产多副本但少于现有工具建议|未评估|建议不是厂商准入下限，不据此断言不支持；需要版本、故障域、仲裁与恢复方案评审，不能确认生产可用|
|POC低于参考建议|提示|保留手动数量，允许作为验证目标，不承诺生产能力|
|反推按既有规则调整副本|提示|逐租户展示输入/实际/工具基线；不新增抬高数量逻辑|
|集中式业务容量或性能初算需要超过1 Group|生产未通过；POC提示|保留1 Group，不擅自改成分布式；调整方案/需求或提供匹配标定后重算|
|反推集中式无业务吞吐和标定|未评估|库存数量、磁盘和落位另验，不能虚构性能结论|

通过仅表示对应工具数量规则或初算边界通过，不是厂商认证。既有工具业务/反推参考值存在差异，本批沿用各模块现有值并明确显示，不擅自统一成新的产品最小副本数。默认业务4副本低于其模式的5副本参考值，现在标为未评估，不自动增配，也不认定产品不支持。
