## 已实现

- 跑批主入口二选一：峰值速率，或总工作量+有效窗口。
- 峰值支持SQL QPS / 事务TPS；窗口支持SQL执行总次数 / 业务处理总量。
- batchRateMode仍为实际计算口径的唯一依据；主入口从它派生，不把旧数据按另一个单位重新解释。两类入口分别记住上次子口径，原数值切换保留。
- 在线及跑批CN的手动规格增加8/16/32/64/96/128/256C快捷选择，对应32/64/128/256/384/512/1024GB；自定义核数、内存仍可输入。
- 性能参考表按当前在线/跑批各自标定计算，输入变化即时更新；无效标定显示待标定，不提供虚构厂商性能。
- CN故障策略贯穿推荐数量、规格、实际落位校验、计算说明、红线及Excel。

## 故障策略及公式

| 策略 | 推荐 | 生产故障要求 |
| --- | --- | --- |
| 原方案（默认兼容） | 按正常吞吐 | 单台物理机故障容量仍作为红线 |
| N+1 | 生产增加1个CN实例余量，再应用原偶数规则 | 实际单台物理机故障后完整目标，失败仍报红线 |
| 正常峰值 | 按正常吞吐 | 单机故障仅提示，正常容量不足仍报红线 |

设每AZ目标D、每核标定k、水位w、允许核数上限C：

- 原数量：max(2, ceil(D / (k*w*C)))，再按原规则可选取偶数。
- N+1生产数量：max(2, ceil(D / (k*w*C)) + 1)，再可选取偶数。
- N+1自动规格：用n-1个实例分担D，选择原有规格档位且不超过宿主机允许的核数。
- 手动数量、规格不自动抬高；若(n-1)*c*k*w < D，提示实例余量不足。
- 最终实际单机检查仍为：(有效实例数 - 单台服务器承载该场景的最大实例数)*c*k*w >= D。
- 一台物理机可能承载多个CN，因此多1实例不能直接证明单物理机故障通过。POC不强制增加N+1数量，仍保留故障提示。

窗口模式沿用原有独立效率、停顿、重试及实际落位检查。正常峰值策略不取消用户明确输入的不可用CN数及窗口不足检查，只将额外单机故障场景降为提示。N+1数量本身不替代窗口检查。
