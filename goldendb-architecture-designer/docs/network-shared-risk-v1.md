# 已知共享风险与跨目录资产核对 v1

2026-11-01，P02b3b2b1c2a。本批识别已声明路径中的已知共享资源，以及网络设备和数据库主机的同号物理资产冲突。它不能证明两条路径物理独立。

## 输入与计算来源

无需新增手工结果字段。物理检查器遍历当前路径、备选路径时，提取已访问声明中的端口、线缆、交换转发、归属对象、交换/路由设备资产，以及已有 faultDomainIds。端点物理端口单独保留，不因“端点天然相同”就忽略它们。

共享比较仅针对同一逻辑邻接的当前活动路径与其每条备选路径，不做所有备选之间、不同逻辑邻接或整条业务跨路由路径的全量两两比较。物理路径中未解析的段不会伪造资源；已知交集即使与未知项并存仍展示，缺项不能据此当零。

共同归属使用带类型的对象标识：主机H和交换机H不因短ID相同就误认一个对象。页面显示中文归属类型和对象编号；JSON保留结构化结果供核查。路由/交换资产按现有assetId精确比较；数据库主机的physicalId由生产契约另行核对，未假定主机逻辑ID就是资产ID。

## 输出与解释

|结果类别|内容|结论边界|
|---|---|---|
|network-shared-risk|当前/备选路径ID、分类型共享资源、共同端点端口、比较状态|发现共享时显示“存在已知共享，冗余未评估”；否则仍为未评估|
|network-asset-identity|数据库物理主机与网络设备的同号资产冲突|冲突阻断独立资源模型；无冲突不证明身份独立|

共享风险行不直接把当前可达性判为失败：共同端点并不意味着当前通信一定失败，但可能成为共同故障点。对于要求冗余的生产方案，必须继续核对保护范围、故障场景和剩余能力；本工具尚未实现完整独立性验收门禁。

comparisonComplete只表示本次比较所用两条派生路径检查状态及字段/预算满足比较条件，不代表物理资产、故障域全集已采集，更不代表现场核验完成。independenceProven、identityProven始终false；canDeploy仍为false。

物理遍历得到的resources为计算输出，不能在输入paths中手工填写或声称通过。最多处理20000行派生记录；单类型资源数组最多5000项；累计检查100000个候选资源标识。预算不足保留未评估及已知交集，不把未遍历部分当作无共享。

## 跨目录资产规则

在生产契约中，将topology.hosts[].physicalId与fabric.devices[].assetId、physical.switches[].assetId精确匹配。同号时不能再把它们计作独立物理设备，输出cross-catalog-asset-alias阻断并列出对象。

这可能表示重复登记，也可能表示实际存在共宿/虚拟化。当前独立设备模型不能自动区分或授权共宿；应统一物理身份，并补充适用的共宿和资源约束后再评审，不能只改个编号消除提示。

同号核对以这些字段是共同物理资产命名空间中的标识为前提；不同CMDB的局部编号应先在资料中加以限定并提供可追溯映射。本批不自动忽略大小写、去除前后空格或模糊合并；不同编号但同一物理设备的别名尚待c2a2契约和证据支持。

## 组网实施判断

当前每个逻辑接口采用one-to-one物理端口绑定。同一逻辑邻接的多条物理候选会共享端点端口；仅改变中间交换路径，无法证明对该共同端口故障的保护。若生产目标是端到端双归属，须补充独立接口、独立逻辑路径、真实bond/LAG/路由策略、共同电源/管道和切换验证，不能由“有两条路径”推断已实现。

故障域ID相同表示已声明的共同风险；ID不同仍可能实际共用电源、机柜、管道或同一设备。共同故障是否使两条路径同时不可用取决于实际冗余结构和保护范围，本批只指出可能性。

## 依据与准确续接

[RFC 6372 §4.9.2](https://www.rfc-editor.org/rfc/rfc6372.html)说明逻辑路径多样性不足以证明底层资源独立；[RFC 6414 §3.1.10](https://www.rfc-editor.org/rfc/rfc6414.html)给出共享风险链路组的概念。参考[Batfish转发分析](https://github.com/batfish/batfish/blob/master/docs/forwarding_analysis/README.md)对派生路径及信息不足的处理边界；本工具独立实现有限声明检查，不模拟其完整控制平面或符号分析。
