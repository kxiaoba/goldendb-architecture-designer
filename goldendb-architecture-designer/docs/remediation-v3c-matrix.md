## 2. 两处已复现并修正的缺陷

### F1 小数资源精确边界误报不足

两个DN各需0.1TB、0.2TB，目标净预算0.3TB。原普通累计得到0.30000000000000004，大于0.3，导致联合重建错误报告存在缺口、试排0个。修改后使用补偿累计，并仅在比较时允许8倍机器精度的相对舍入误差；目标预算本身不变，也没有固定容量下限。相同夹具现在试排2个，结论仍是“预算内可排布（仅必要条件）”。

验证：1000个0.3TB的Group累计为300TB；0.300000001TB仍不能装入0.3TB；极小预算1e-300不能装入2e-300；预算0不会容纳最小正数。明确0TB业务仍拒绝任何正数据，不以浮点容差夹带容量。

### F2 显式逐Group数组缺项被均匀值掩盖

2个Group、单份总量0.3TB，显式数组[0.1]或稀疏数组。原底层对缺失G2退回0.3/2=0.15TB，仍被视为有效需求。修复为：显式数组必须长度匹配、无空洞、元素均为非负有限数，否则需求未知、资源审计不通过；副本覆盖也不能借旧resourceAudit将无效需求计作有效副本。只有未提供逐Group计划时才采用原均匀假设；显式0值保持0。

边界说明：普通UI原本已通过JSON/长度校验拦截不完整输入；本次补齐底层需求、候选和变更后对象的保护，不宣称原UI一定能输入绕过。完整合法数组的求和/增长校验仍由原解析链负责。
