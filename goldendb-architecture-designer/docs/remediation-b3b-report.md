## 实现与口径

新增交易峰值年增长系数，默认 1，最小 1，与数据增长系数独立。1.2 表示每年乘以 1.2，而非增加 1.2 个 TPS。规划年限为 0 时两种倍数均为 1。

- 当前事务 TPS = 租户 QPS / 每事务 SQL 数。
- 规划 TPS = 当前事务 TPS × 交易峰值年增长系数的年限次方。
- 规划数据量 = 当前数据量 × 数据年增长系数的年限次方。
- CN 数量先计算规划 TPS，再除以基准安全能力并向上取整，最后应用原最低节点/取偶规则。不再先取整节点数再乘增长倍数。
- DN 性能分片和 DN 规格同时使用规划 TPS；容量分片使用规划数据量。
- 自动建议与实际计算引用相同时间口径，手工数量保留，低于能力要求时触发原有红线。
- 页面公式区说明增长倍数；Excel 租户资源增加规划事务 TPS 列，反推模块没有业务量时填“未评估”，不伪造性能数据。

影响文件：`app.js`、`index.html`；新增增长测试，更新 CN 测试以使用明确的交易增长参数。没有修改装箱、反亲和、GTM 绑定、机房策略或副本规则。

## 旧方案迁移说明

原数据增长系数曾错误地影响 CN，但不影响 DN 性能。本批不自动把数据增长复制为交易增长：旧方案重新录入时，必须分别确认两种系数；交易增长默认 1 不代表已经确认无需增长。旧导出文件不被修改，也未增加上传导入功能。

这里使用的是用户输入的复利规划假设和算术一致性，不是 GoldenDB 厂商增长预测或实测性能保证。不能由数据增长推导交易增长；不同业务可独立填写。现有单核线性能力、内存比例及硬件适配边界仍需 POC。
