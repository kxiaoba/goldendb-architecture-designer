# R18a GTM扩容对比与用途保护验收记录

日期：2026-10-27；基线eed18e3加已验证本地R07/R08/R13/R14。本批完成R18a诊断保护，R18整体尚未完成：R18b保留现网绑定与物理落位的增量规划器仍待实施。

## 复现事实

业务和反推模块均可复现：自动GTM模式下，已有两个共享GTM的分布式租户，新增第三个独立部署租户后，整个新方案变成专属GTM，已有两个租户的绑定一起变化。原代码按全体租户重新选择单一全局kind（shared或dedicated），这适用于新建重算，不能直接等同现网扩容。

本批没有锁定或修改数据库现网，也没有声称已经让旧共享GTM与新专属GTM在同一增量模型中正确落位。实际厂商版本、Group标识、绑定配置和现网宿主机未提供，不能从规划文本推断其迁移可行性。

## 已实现功能及保护

1. 新增规划用途：默认“新建／重新规划”，以及“现有集群扩容对比（仅诊断）”。新建保留原计算和重排行为；对比用途不改变数量或算法，而明确表明重算结果不能直接作为实施方案。
2. 两模块分别保存本页工具基线：稳定租户ID、GTM共享/专属语义、各组副本数、资源池、拓扑、规划GTM角色的工具Server编号/中心/池。快照脱离模型对象，始终标注未经现网核验。
3. 逐租户展示新增/移除/既有配置变化/绑定资源池未变，列出前后绑定、副本与资源池；汇总Group/实例数变化、相同GTM角色的工具落位编号变化。租户改名不伪造新租户或绑定变化；集中式不在GTM主路径的情况单列。
4. 扩容对比中已有基线锁定，按钮和函数均不能覆盖；明确切回新建重算才可替换。清除或缺少基线时保持未评估，非法输入不能保存、导出或覆盖基线。
5. 所有扩容对比结果都保持诊断限制，哪怕未发现绑定差异：尚未固定现有CN/DN/GTM物理落位，也未验证现网。加入部署红线；反推结论不宣称可执行扩容，启发式高分只能诊断。PNG带“本图仅供排查”。
6. 保护和差异同步到页面、风险、公式、复制摘要、Excel摘要/风险表、服务器/网络PNG；新建模式的公式/摘要/Excel/PNG也明确标出重新规划用途，不保证保留现网绑定，并可真实下载JSON对比记录。JSON是工具记录，不是生产配置或迁移脚本。

## 使用步骤与会话边界

先在对应模块生成原规划，点击“保存当前方案为工具基线”；再选扩容对比并增删租户/改变绑定参数，检查逐租户差异，下载记录及Excel。需要替换工具基线时先切回新建重算，这一动作不代表现网迁移已经发生。

基线仅在当前页面会话内有效；切换模块分别保留，刷新或“全部重置”清除，界面已明确说明。JSON可存档但本批不支持导入恢复；不能单独恢复旧工具ID再套用全新参数，避免错把不同对象当同一现网租户。用户要求的代码修改续接由本批checkpoint与完整计划负责；它与浏览器会话基线是两回事。
