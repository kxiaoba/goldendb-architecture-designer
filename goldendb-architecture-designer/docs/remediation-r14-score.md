# R14 评分偏好与实际方案语义验收记录

日期：2026-10-27；基线eed18e3加本地已验证R07/R08/R13。本批修正反推评分与结论语义，不新增优化器，不重算旧分数或修改规划参数。

## 已复现事实

反推双中心120台、128核/1024GB、已填写数据需求，切换三个目标得到96/97/94分，但实际租户、数量、规格和服务器落位相同。标题却写“资源反推最优方案”。当前入口的goal只选择评分权重，没有执行全局方案搜索；旧辅助函数存在不代表当前入口调用了它们。

进一步将管理节点设为1，工具已有一条管理节点红线，但仍给94分，最终结论仍为“可作为生产架构初稿”。分数没有覆盖所有准入风险，不能被解读为生产可用率、性能认证或完整可行性指标。基线与修正证据分别保存baseline-defects.json/fixed-probe.json。

业务模块的机型策略是另一条路径：推荐机型下的性能配置会将DN单机上限从2调整为1，存储/均衡配置按原规则处理。它不是反推加权偏好，因此保留业务策略及所有手工机型参数，没有做全站文字替换。

## 修改

- 标题改为“资源反推参考方案”；“设计目标”改为“评分偏好”，明确仅改权重、不调整数量/规格/落位；选项为均等权重、计算数量项优先、副本/共宿项优先。
- “综合评分/性能/可用性/容量”改为“启发式参考分/计算数量项/副本共宿项/库存余量项”，展示权重、分项、原计算式和实际部署红线数，不将分数当实测指标。
- 有任何现有部署红线时，分数标为“仅供诊断”；无当前工具红线时也只为“仅供偏好比较”，并明确未证明生产可用。
- 反推结论补齐所有现有部署红线检查；管理节点不足等不能再仅凭高分或库存充足给可用初稿结论。保留更具体的身份、水位、容量不足诊断。
- 同一评分说明贯通风险列表、方案卡片、公式、摘要复制、服务器视图、Excel摘要/风险表和实际PNG。反推PNG有任何部署红线均显示“本图仅供排查”。
- 业务模块无反推评分，新加说明不向业务页面虚构评分；独立固定数量工具保持原逻辑。

## 保留的算式与权重

各分项先ROUND并截断到0..100；总体加权后ROUND。均等权重三项各1/3；计算数量项优先为50%/25%/25%；副本共宿项优先为25%/50%/25%。原scoreReversePlan、clampScore及其返回字段/值未改，便于历史比对。

P=65+CN/AZ×6+Group总数×2，资源状态不足扣30；A=72或88（原DN共宿规则）+最大副本数×4，生产且允许共宿扣18；C=80+MIN(12,库存数-所需数)×2，临界扣12。它们只是旧数量模型，不会验证SQL、CPU/IO、仲裁、切换、备份或恢复。使用最大副本计入A并不证明所有租户具备同样保护，本批仅公开这一局限，不擅自替换评分模型。
