# 新增租户相对约束契约 v1

R18b2a只读检查器：`GoldenDBIncremental.validate(input)`。它比较基线与候选，禁止新增租户时静默改变既有对象；不导入规划状态、不自动试排、不调用数据库。检查通过只是文件约束一致，不是扩容实施准入。

## 输入

|字段|要求|
|---|---|
|schema|`goldendb-incremental-constraints-v1`|
|operation|本版仅`add-tenants`|
|label|可选的展示说明|
|baseline|完整`goldendb-expansion-baseline-v1`，已有实例必须已落位|
|candidate|同版目标快照，含全部已有对象和全部新增对象|
|additions|sites/pools/hosts/tenants/groups/instances六个ID数组，无新增也须写`[]`；精确等于候选ID集合减基线ID集合|
|baselineIdentityMap|显式`null`表示全部未知；否则提供上述六类数组，每行`{id,externalId}`，恰好覆盖每类基线对象|
|newHostIdentityMap|无新增主机须为`[]`；有新增主机可显式`null`保持未知，否则逐行`{id,externalId}`精确覆盖新增主机|

顶层不接受额外批准、迁移或覆盖标记。原生ID可显式`null`；字符串须非空、无首尾空白/控制字符/未配对代理字符且不超过256字符，同类原生ID不得重复。新增主机原生ID不得与已知基线主机或另一新增主机重复，防止同一物理资源重复计数。未知旧映射无法排除与新映射冲突，仍为未评估。映射和来源均为文件自报，不因字段完整而成为已核验事实；需要外部清单和人工核对真实身份。

对象数量、稳定ID及资源单位沿用[基线契约](expansion-baseline-contract-v1.md)，界面文件最大2MiB。源码比较有250000步预算；预算耗尽标记未评估，不推断物理方案不可行。

## 保持规则

- 基线来源/版本、策略和其他根元数据保持；既有站点、资源池、主机和实例的完整记录保持。实例ID、宿主机、角色、组/租户归属及资源需求均不可改。已有对象不可删除、重编号或换成另一对象。
- 既有租户只允许名称变化，报告列出改名；原CN目标、允许池、DN集合和GTM绑定保持。名称不是身份键。
- 既有组副本目标、主中心、允许池等保持。仅允许新增租户加入既有GTM组，保留原成员；禁止移除原租户或将既有租户重新绑定。新专属GTM组可与原共享GTM组并存。
- 新组只能为新增租户拥有的DN/GTM组；新增CN/DN只能属于新增租户，新增GTM实例只能属于新增组。副本数、双向组归属、主中心、跨主机、逐站点、池/隔离及联合预算继续由基线校验器检查。
- 本版不处理新增站点、既有租户扩分片、控制面/运维CN扩容、主从切换、升级、既有角色迁移或策略修改；这些操作须另建受控变更，不能借新增租户绕过锁定。
- JSON对象属性顺序不构成变更；DN组/允许池列表按集合语义比较；其他有序数组保持其原语义。不修改输入或共享其报告引用。

## 待落位与状态

仅候选相对基线真正新增的实例允许`hostId:null`，不能省略字段，也不创建虚拟主机。已有实例必须保持原宿主机。新增已落位实例继续接受完整结构/密度/资源检查；部分未落位时也检查已落位部分是否超出站点配额、违反主中心或反亲和。

`GoldenDBBaseline.validateTarget(candidate,newInstanceIds)`是目标快照校验辅助接口，只允许显式新增集合的空宿主机；基线严格入口`validate`仍拒绝未落位实例。实际相对检查中新增集合由ID差集计算，不信任调用方自称已有实例为新增。

|返回字段|判读|
|---|---|
|valid|仅无已发现错误，未知时也可能为true，不能单独作准入条件|
|structuralStatus|未通过 / 部分未评估 / 输入约束通过（非实施准入） / 未评估（比较预算超限）|
|existingLockStatus|逻辑锁定检查通过（文件范围）/未通过/未评估；绝不是现网绑定已核实|
|mappingStatus|现网映射未评估 / 映射格式已提供（真实性未核验） / 未通过 / 未评估|
|placementStatus|新增实例待落位或候选落位已提供；始终说明未执行自动试排|
|capacityStatus|只比较录入预算；需求、主机预算或落位缺失时未评估|
|productionStatus|始终未评估|
|lockedInstances / unplacedInstances|基线既有角色锁定清单 / 新增待落位清单；删除候选对象也不会使其从基线锁清单消失|
|delta / renamedTenants|六类前后数量及新增数量 / 名称变化记录|

errors/unknowns各最多保存300条，完整errorCount/unknownCount决定状态，不能因截断把错误或未知变成通过。界面只预览部分条目，完整报告可下载。

## 示例与续接

`examples/incremental-add-tenant-synthetic.json`是单独的学习样例：60台库存、原2租户共享1组GTM，38个实例；新增T3独立GTM及1个DN组，候选56实例，18新增实例全部待落位，38旧实例保持。这与用户原60台/24+3+1分片/212实例用例不同，不应混用容量结论。

样例原生映射、硬件预算、实例需求与版本未知。手工已落位正向样例只用于回归，不是已实现的自动增量规划器。下一步R18b2b应消费本契约的逐组归属和旧角色锁定，设计有界试排及缺口诊断；R18b3再做完整差异、导出和实施边界验收。
